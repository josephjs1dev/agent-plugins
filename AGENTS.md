# agent-plugins

## Project context

agent-plugins holds plugins for several agent hosts. Each plugin keeps
host-neutral logic in `packages/<plugin>/` and one adapter per host in
`<host>/<plugin>/`. The plugins are Conductor (a Paseo adapter in
`paseo/conductor/`, with a bb adapter planned in `bb/conductor/`) and
Essentials (a Paseo adapter in `paseo/essentials/`).

Hosts install one plugin directory on its own. So each adapter commits a copy
of its core, generated by `scripts/sync-core.mjs`. The sync places each core
module by the host's runtime rules (Paseo: Node-free modules in `shared/`, the
rest in `server/core/`) and rewrites imports. The adapter's `.core-files` lists
the generated files. Edit them only in the core, then
run `node scripts/sync-core.mjs <plugin> <host>`. Conductor data lives in
`$CONDUCTOR_HOME` (default `~/.conductor`) for every host.

## Repository guide

Read [README.md](README.md) for the layout and plugin catalog. Before changing
Essentials, read [the core README](packages/essentials/README.md) and
[the Paseo README](paseo/essentials/README.md). Before changing
Conductor, read [the core README](packages/conductor/README.md) and
[the Paseo README](paseo/conductor/README.md).
For frontend work, also read
[Frontend Coding Styles](.agents/rules/typescript/frontend-styles.md).

Put all plugin logic in `packages/<plugin>/src/`. Cores have no entrypoints.
Hand-written adapter `server/` code holds only entrypoints and host glue that
call the core. Keep host SDK
imports out of `packages/<plugin>/`. Domain code reaches a host
through its `host.ts` ports. Keep each adapter independently installable, with
its own manifest, package, lockfile, runtime entries, README, and validation
scripts. Keep dependencies pinned and update the lockfile when they change.

## Validation

For a core, run `npm run check` in `packages/<plugin>/`. For an adapter, run
`npm run check` in `<host>/<plugin>/`. The adapter check first fails on core
drift. It runs type checking, linting, formatting checks, and tests. Tests use temporary
files and fake processes/HTTP responses; they do not require real credentials.
Live installation, reload, and visual verification are separate actions.
Run `git diff --check` for changes across the repository.

## Canonical instructions

Keep shared rules and personas in `.agents/`. Reserve `.codex/` for native
configuration and command permissions. Edit `AGENTS.md` as the canonical project
instruction file and preserve the `CLAUDE.md` symlink to it.

## Commit and push

After completing changes and relevant validation, summarize the result and ask
whether to commit and push. Offer Commit and push, Commit only, and Leave
uncommitted. Do not commit or push without authorization; reuse authorization
already given for the current changes. Keep unrelated changes out of the commit.
